# ppt-master 集成

本包依赖宿主已安装且完整性检查通过的ppt-master。通过宿主Skill加载获得实际绝对目录，doctor仅提示环境，不执行或绕过其完整性检查。若宿主不能加载，报告缺依赖；不以其他PPT库静默替代后声称执行了ppt-master。

## 创建论文PPT

读取当前SKILL及路由，普通“做论文两版”属于Generate PPTX；不是Beautify（不保持旧PPT字数/页序），也不是原生编辑既有deck。分别初始化两个工程，内容来自共同content与plans。遵守当前运行路由的角色、确认/委托、设计与锁文件、页面、备注、图表检查和导出顺序。用户没有要求Quick就用Default；不得为了省事略去关口。

默认模板是本Skill下的完整工作区根`assets/neutral-academic_20261017`。传递绝对root作为明确候选；不能只复制其中几张SVG充当已经应用模板，不能传inner templates目录。使用依赖当次apply-template契约及结构元数据。依赖升级时先用小样验证；不假定旧roundtrip流程可用于新生成模板。

模板已有一个Master与若干独立布局。保留布局槽位契约，同一布局key不能任意改变槽位/固定元素；正文过长时拆页，或由适用路由允许的自适应机制声明新布局。独立图表/原文图片和来源要在最终SVG完整呈现；导出器不应替作者补可见内容。

## 逐页制作注意事项

以下是论文长文档实际制作中反复出现的问题，属于流程要求，不替代 ppt-master 的说明：

- **左右对照页先定锚点再画。** 先算右侧每条解读的首行基线，再把编号徽标和箭头画在这条基线上；不要以左侧高亮行作为编号位置。
- **结构层先占位。** 右栏段落总结、页面标题、页脚、图注在开始画之前先固定位置，后续加标注不得挤占。
- **集中映射。** 页脚出处、图表号、章节号用一张 `页码 → 出处` 映射表统一生成，继承页与重写页共用，避免只改重写页。
- **导航按输出页。** 章节高亮按最终页序判定；附录页另行处理，不沿用源页。
- **动画按类和按页写。** 用配置驱动（页面 → 组 → 效果顺序），同类页面同一顺序；未配置页面显式写 `none`，避免残留。
- **改版后重新导出再渲染。** 交付记录里必须写明本次成品对应的检查日志与哈希；旧日志不能当本次证据。

## 自制模板

中性模板使用Create Template→Create Deck，因为它携带论文讲解场景和视觉/结构规则。采用新建工作区，不修改原文件或依赖全局模板索引；由显式root消费。Create Template不直接填充本次论文内容，论文成品属于后续独立Generate生命周期。新建/修改模板时重新遵守其简报确认、委托审阅、规范与包验证。

模板未复制旧PPT素材。白底蓝色属于本包自选方向；这不构成原模板的脱敏认证，也不授予原PPT再分发权。预览PPTX为派生检查样例，不替代templates工作区。

## 常见错误

- 不把固定“18页”“7句摘要”、具体模型或样本写进通用断言。
- 不复制旧finalize脚本中硬编码通过状态。视觉未检查时保持pending。
- 不为新工程直接使用旧PPT的shape-ID与裁切坐标。
- 不把主题重写称作1:1Beautify，不将原模板metadata带入分享包。
- PDF导出工具和路径由环境检查取得；不写死用户名和盘符。未安装可报告缺依赖，不擅自安装系统工具。
- 不把旧一轮的几何日志、交付 JSON 或备注清单当作新成品的证据；换版后必须重跑并写入记录。
