# 论证完整性与结构层核查

本文件回答一个问题：**一页讲完后，读者的理解是否与论文一致，且没有丢东西。** 它补充 `content-contract.md`（数据契约）与 `acceptance.md`（关口），专门针对实际制作中最常出现的十二种缺陷。

## 1. 需求、设计、实现三分

论文常把「研究发现的问题」与「系统做了什么」写在同一段。页面上必须分开：

| 层 | 来源 | 页面位置 |
|---|---|---|
| 需求 / 挑战 | 形成性研究的主题与原话 | 挑战卡、需求栏 |
| 设计回应 | 论文明确写的设计决定 | 设计栏 |
| 实现差异 | Table 中的具体参数、界面元素、流程 | 单独的实现页或表格 |

**硬规则**：不得把系统实现（如「八场景模板」「credit scene」）写进「需求」栏。判断方法：如果这句话描述的是界面或流程而非参与者的诉求，它属于实现。

## 2. 样本与分母

任何数字出现前，先确认它属于哪个样本：

- 形成性研究的参与者是否计入最终评价的人数？
- 同一批人是否既制作又评价（同一份问卷里出现两次）？
- 图表标题里的 N 是总人数、有效回答数，还是分组后的人数？
- 条件组人数是否相等？不等时不得写成「每组 N=x」。

页面与备注都必须写出该数字的分母来源；两版之间同一数字的分母必须一致。

## 3. 统计读数

- 非显著 ≠ 等效 ≠ 排序。均值接近但未检验，不能写成「几乎没有差异」；差异不显著但均值有高低，不能写成「A 优于 B」。
- 均值最高维度数要写清「几维中的几维」，不能只说「多数维度最高」。
- 反向题（量表正负向相反）必须逐题核对方向。若论文自己把反向题算进「最低」，页面要标出这与图不一致，而不是跟着错。
- 误差线类型（SE / SD / CI）与量表点数写在图注或页脚。
- 显著性水平：写原文给的阈值，不把 `p < .1` 说成「显著」，也不把 `p < .05` 说成「高度显著」。
- 效应量与样本量：原文没给就不补；不根据柱高估算精确均值。

## 4. 三类「之后」

论文末尾常混放三种东西，必须分开标注：

| 类别 | 含义 | 视觉处理 |
|---|---|---|
| 作者提出的未来工作 | 论文明确写「future work / we plan / future research」 | 常规分组，标「作者」 |
| 风险或开放议题 | 作者描述的问题、担忧、未解决争论，但没提出方案 | 标「风险议题」，不使用未来工作时态 |
| 我们的建议 | 讲义或课堂讨论提出 | 标「我们的讨论」，与上述两类分栏 |

**硬规则**：未实现的能力不能画在系统能力图里；系统页只画当前可做的操作，做不到的另起一栏并注明限制来源。

## 5. 局限的归属

局限拆两类，不合并：

- **作者自述**：论文 Limitations / Discussion 中的原句或紧邻改写，注明物理页。
- **讲义补充**：由证据边界推导的课堂提醒（例如「该量表测的是感知，不等于客观学习」）。必须写「讲义补充」，不得伪装成作者原话。

## 6. 引文真实性

- 页面上任何引号内英文必须逐字来自原文；删节用省略号并注明；不得自拟英文再署作者名。
- 「作者指出」「论文认为」这类转述，必须在备注给出可检索的原句与物理页。
- 若无法定位原句，改写为「本讲义概括」并去掉引号。

## 7. 结构层保护

以下内容属于结构层，任何重排、加标注、加动画都不得删除或遮挡：

- 右侧栏顶部的段落总结；
- 页面标题与导航标签；
- 页脚出处、页码；
- 图注与来源；
- 表格的列名与单位。

若空间不足：先减少解读条数，再拆页，最后才考虑缩小字号；不得为了塞内容删掉结构层。

## 8. 导航与继承

多章节长文档常由同一母版继承而来。规则：

- 导航高亮必须按**输出页**所属章节判定，不能沿用源页。
- 附录页隐藏或另设导航状态，不显示上一章节的高亮。
- 页脚、页码、导航三者一起改；只改一处就会出现「这一页还显示上一章」。
- 继承页与重写页使用同一套集中映射表生成页脚。

## 9. 交互与流程的解释

系统论文的流程页要回答三件事：输入是什么、人做哪些决定、输出是什么。只画方框不标「谁在决定」，读者会误以为全自动。凡是 AI 生成 + 人修改的环节，必须标出人的介入点。

## 10. 图表读法

每张图在页面上至少回答：这张图在比较什么、横纵轴与单位、误差线含义、最值得看的一两个数、不能从图读出的结论。完整原图放不下时进附录，主体页给关键区域与图注。

## 11. 一致性

同类页面使用同一结构：同样的左右比例、同样的编号位置、同样的「→」前缀、同样的页脚格式。用户提到的「前后不一致」通常就是这几处。改一处要全篇同步。

## 12. 自评诊断

在把成品交给用户前，自己先按本文件逐条过一遍，列出「已知缺口 / 已知不一致 / 需要外部条件」三类。用户明确要求过：不要只报通过，要把还剩什么说清楚。
